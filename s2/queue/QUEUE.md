# Очередь задач в PostgreSQL

[schema.sql](schema.sql) создает очередь `queue_task`, журнал бизнес-событий и
частичный индекс для выборки готовых задач. Producer добавляет задачу и
связанное бизнес-событие в одной транзакции. В 20% случаев задача получает
приоритет `100`, в остальных случаях `0`.

Два worker-процесса конкурируют за задачи через:

```sql
FOR UPDATE SKIP LOCKED
```

Благодаря сортировке `priority DESC, created_at` критические задачи выбираются
раньше обычных. При имитации ошибки задача возвращается в очередь с задержкой
пять минут. Для борьбы с bloat заданы более агрессивные настройки autovacuum.

Запуск:

```bash
psql -d carservice -f schema.sql
dotnet run -- producer
dotnet run -- worker worker-1
dotnet run -- worker worker-2
```

В конце [schema.sql](schema.sql) находятся запросы для измерения лага самой
старой задачи и суммарной пропускной способности worker-процессов.
